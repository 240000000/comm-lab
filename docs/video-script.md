# 录屏脚本（照着录就行）

目标时长 5 分钟左右（5:00–5:40 都行）。全片是我自己的口吻，不用配乐，不打字幕条，屏幕录制 + 麦克风就够。

**录之前先摆好这几个窗口，不然录到一半切窗口很难看：**

1. 浏览器标签一：`https://240000000.github.io/comm-lab/`（线上版，首页）
2. 浏览器标签二：GitHub 仓库的 `docs/dialogues/2026-10-26-session-02.md`（要能上下滚动，字体调大到能看清）
3. 终端窗口：放在另一个桌面或最小化，复现那段要用
4. 浏览器缩放 110%，录屏分辨率 1920×1080

每一段我写了两行：**嘴里说**是能直接念的句子，**屏幕上**是手要做的动作。念的时候不用一个字不差，但别加"赋能""闭环""助力"这类词。

## 0:00–0:30 开场：我为什么做这个

**屏幕上：** 停在线上首页，四张卡片都在画面里。光标停在第一张卡上不动。

**嘴里说：**

> 通信原理这门课，我背了一学期的公式。QAM 星座图长什么样、误码率随信噪比怎么走、卷积码为什么能纠错，考试的时候我都能写出来，但换个信噪比我就不确定自己算得对不对。
>
> 问题不是不会算，是看不见。星座点被噪声推散是什么样子，一帧比特里哪几位被打翻了，译码器凭什么说这几位是错的——这些在纸上画不出来。
>
> 所以我把它们做成了网页。这个项目叫「通信原理交互实验室」，打开浏览器就能拖。

## 0:30–1:40 QAM：把滑块从 20 dB 拖到 0 dB

**屏幕上：** 点第一张卡进 `#/qam`。先停 2 秒让画面稳一下，然后从右边滑块最右端开始，**慢慢地**往左拖，一路拖到 0 dB。中间在 12 dB 停一下，让镜头看清云团长出来。

**嘴里说：**

> 这是 16QAM，十六个点，每个点旁边四位是它的格雷码标签。右边这个滑块是信噪比，最右边 20 dB，信号干净，点几乎贴在理想位置上。
>
> 我往左拖。12 dB，每个点开始变成一小团——这就是噪声把它推离原位的样子。再往左，0 dB，整片都是散的，已经分不出原来那个点在哪儿了。
>
> 看下面这三个数。误码率 2.86e-1，括号里是「错 22,916 个比特，共比对 80,000 个比特」——每个数都带着分母，不给你一个孤零零的小数。中间是误符号率，右边是误差向量幅度，99.62%，意思是接收点离理想位置的平均距离，差不多是理想幅度本身那么远。
>
> 再往下这条曲线，横轴 0 到 20 dB，灰虚线是公式算的，实心点是这批样本实测的。20 dB 那个位置画的是个空心圈，因为这一批八万个比特里一个都没错——能分辨的最小误码率就是八万分之一，再低就看不见了，不是真的零。

## 1:40–2:40 卷积码：翻两位纠回来，翻四位纠不回来

**屏幕上：** 回首页，点第二张卡进 `#/conv`。先点「关掉」噪声（让加噪后那行和编码后完全一样），再点「翻 2 位」，停 2 秒；然后点「翻一片 4 位」，停 3 秒，让状态条那行字被看清。

**嘴里说：**

> 换到卷积码。上面这条是 12 个比特，四行摊开：原始、编码后、加噪后、译码后。编码器约束长度 3、码率一半，12 位编成 28 位，末尾那两位淡灰色的是补零——补零是为了让码字结束在一个确定的状态上，不然译码器回溯的时候不知道该从哪儿收尾。
>
> 我先把噪声关掉，这样加噪后那行跟编码后一模一样。现在手动翻两位——看，第四格和第十八格变成琥珀色，这是接收端被打翻的比特。译码之后，12 位全对，它把这两位纠回来了。页面下面这行字写的是「手动翻了 2 位，译码后原样回来了」。
>
> 再翻一片四位。这次它纠不回来——琥珀色有四个，红色格子表示译完还是错的。页面照实写「还有几位没纠回来」，不替我圆。这个码算出来的自由距离是 5，纠错能力是两位，超过两位就超出它的能力范围了，翻四位纠不回来是正常的。
>
> 可以切硬判决和软判决两套译码器。下面这条曲线是三条线：不编码、硬判决、软判决。软判决明显压过硬判决——因为它不先把幅度切成比特，保留了「离门限多远」这层信息。

## 2:40–4:40 AI 协作：我是怎么指挥它的（这段至少两分钟）

**屏幕上：** 切到标签二，`docs/dialogues/2026-10-26-session-02.md`。先快速滚过 `## R1`、`## R2` 的标题（让大家看见一轮一节），然后停在 `## R4` 那段的用户消息上，手指/光标指着"图注把横轴刻度压住"那句；再滚回 `## R1` 里 AI 承认判据写错的那段，停住；最后滚到 `git log` 里那条 `fix(docs)` 提交。

**嘴里说：**

> 这个项目不是我描述一遍需求、它一次生成的。我跟它一轮一轮做，每轮结束把当轮对话原文存进仓库，一个提交一个标签，现在有 R1 到 R5。
>
> 存档里用户那部分是我的原话，AI 那部分也是它的原话——这条规矩是它自己犯规之后定下来的。第一轮它写的存档，我对着屏幕核，发现四句话的措辞跟屏幕上不一样，它按记忆重写了一遍。我要求：存档必须是复制粘贴的原话，拿不到就写「原文缺失」，不许补写；而且不许改旧提交，单开一个修正提交改回来，让「我发现自己没逐字」这件事留在历史里。现在这条修正在提交记录里能看到。
>
> 第二件事，这一轮我让它先别写代码，先写「怎么算做完」。它预测「还没有测试文件的时候，跑测试会失败」——我让它真跑一遍，结果是零个测试、正常退出。它当场承认判据写错了，把判据改成「测试数必须不少于十八条、失败为零」，才动手写代码。
>
> 这是 R4 那轮，我指着截图跟它说：曲线图的横轴标题压在刻度上了。它改了间距，我又截了一遍确认。同一轮还有一次，点云透明度太高，十六团云糊成一片，标签读不出来，也是我截图之后挑出来的。
>
> 它想省事的地方，我自己立规矩。比如某个信噪比下一条错都没有，它一开始想写 1e-5，我说不行：要么写「这次没出错，0/80000」，要么直说样本不够看不出来。曲线上样本不够的地方画成空心，不许硬连。
>
> 还有这一轮的首页，它写了一句「能调 QAM 阶数」，可阶数其实是写死的十六点。我在提交前逐句核对时抓到的，让它改成只写现在真能做到的。这种话评委一眼就能撞见，所以宁可少写。
>
> 它写得很快，但「写得像真的」和「真的」是两回事。这个项目里每一轮，最后都得我自己去核。

## 4:40–5:20 复现：现场克隆一份

**屏幕上：** 切到终端，全屏。逐条敲（不要粘贴，让人看见你真的在敲）：

```bash
cd /d/tmp
git clone https://github.com/240000000/comm-lab.git demo
cd demo
npm ci
npm run dev
```

**嘴里说：**

> 别人要跑起来，就这四条命令。克隆、装依赖、起服务。这台机器上克隆四秒多、装依赖两秒多，加起来不到十秒，然后终端会打印一个本地地址。
>
> 整个项目纯前端，没有后端、没有数据库，也不需要任何密钥——仓库里有个 `.env.example`，里面写的就是「本项目不需要配置」。
>
> 测试也是原生的，用 Node 自带的测试运行器，六十八条，跑一遍不到一秒。没装任何测试框架。
