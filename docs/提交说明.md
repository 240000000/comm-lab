# 提交说明

## 一、这个包里有什么

- `comm-lab/`：仓库全部源码，含 `docs/` 下的技术报告源文件、每轮对话存档 `docs/archive/`、`tests/` 与三条原理短片。
- `comm-lab-技术报告.pdf`：技术报告，{{PAGES_REPORT}} 页。
- `comm-lab-作品介绍.pdf`：作品介绍，{{PAGES_INTRO}} 页。
- `提交说明.txt`：就是这份说明。

包根一共 {{FILES}} 个文件，`comm-lab/` 里的源码对应仓库 tag `{{TAG}}`。

## 二、先看哪个

建议顺序：先看技术报告，它按「我要做什么 / 怎么做的 / 为什么这么做」写全了；再看作品介绍，一屏就能看懂这个项目在干什么；最后翻源码，算法在 `src/core/`（全是纯函数），界面在 `src/labs/`。

## 三、怎么跑起来

Node 20 以上即可，不需要装其他全局工具。

```bash
npm install
npm run dev      # 本地开发，终端会打印本地地址
npm run build    # 出静态文件到 dist/，直接用任意静态服务器托管
```

纯前端：不接后端、不连数据库、运行时不调用任何模型接口、不需要任何密钥，断网也能跑。

## 四、怎么核对里面的数字

包里写的每个数都能现场重算，发现对不上请以命令输出为准：

```bash
npm test              # {{TESTS}} 条测试
npm run check:docs    # {{ASSERTIONS}} 条断言，对不上会以非零退出码结束并打印文件名与行号
```

测试只用 Node 自带的 runner 和 assert，文档里的数字由 `scripts/check-docs.mjs` 用 `src/core/` 同一套函数复算，CI 里也跑这两步。

## 五、这份说明本身

本文件是 `docs/提交说明.md`，打包时由 `scripts/pack.mjs` 把上面那些占位符替换成当场算出来的值，再写成包根的 `提交说明.txt`；正文里一个具体数字都不写，所以它不会随轮次过期。
