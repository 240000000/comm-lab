`src/core/metrics.ts` 的 `simulateAwgn` 只接受「符号数」、分母固定是 `symbolCount × 每符号比特`，没法直接表达「我只要前 101 个比特」。所以新题会在新文件里按同一套 `deriveSeed` + 同一条噪声流单独跑一遍仿真，再把「能被每符号比特数整除」的情形与 `simulateAwgn` 逐字段对齐，写成测试。这样既保住 QAM 页的代码路径，也保住「分母严格等于我填的比特数」。

## 判据（6 条主判据 + 1 条边界，点头后照这个验收）

**C1 同参复现，答案现算不写死**
- 同一组参数生成两次，题目对象逐字段相等（真值、种子、符号数、比特数）。
- 参数能被每符号比特数整除时，真值与 `simulateAwgn({order, snrDb, symbolCount, seed: 20261027})` 的 `ber`、`bitErrors` 完全相等。
- 改一个参数（比如 12 → 12.5 dB）真值必须变；代码里没有任何「按参数查表」的答案。

**C2 判分容差，页面上写明**
- 容差取 `max(真值 × 10%, 1e-5)`，闭区间；和现有数值题一样是 ±10%，`1e-5` 只是五位有效数字的绝对底。
- 贴边算对（差 = 容差）、超出一丁点算错（差 = 容差 × 1.0001）。
- 真值为 0 时只认 0（高信噪比、小样本很常见），填 `1e-5` 算错。
- 判分前不显示真值和错位数；判分后才揭晓「仿真答案 + 错了几比特 / 共几比特」。
- 页面上常驻一行：`容差：|你填的 − 仿真值| ≤ max(仿真值 × 10%, 1e-5)；仿真值为 0 时须填 0。`

**C3 非法参数报错，不默默算**
- 阶数 3 / 8 / 256；信噪比 -1 / 20.1 / 30 / NaN；样本量 0 / -5 / 200001 / 1.5 / NaN —— 一律中文报错，不生成、不保存、不进仿真。

## R19 · 2026-10-28 · 首页动态星座背景
