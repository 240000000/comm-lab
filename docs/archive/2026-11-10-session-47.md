## 改法（`src/core/course.ts`，只碰第 5 章）

文件顶部常量，照 `EYE_SEED`/`BAND_SEED`/`QAM_SEED`/`PLL_SEED` 的写法顺延：

```ts
// 绘图用噪声的种子：固定常量 + 四元参数组合，保证同参数同图、换参数必换图。
const MIX_SEED = 20261113
```

`computeModulation` 里，在 `const failed = envelopeFail || threshold` 之后、`series` 之前插入：

```ts
// 只给绘图用的含噪解调波形：σ 由「输出信噪比」读数换回幅度比，读数本身仍走理想路径。
const mixSigma = Math.pow(10, -outSnr / 20)
const mixRng = createRng(
  MIX_SEED + mode * 1009 + Math.round(m * 100) * 31 + Math.round(beta * 10) * 17 + Math.round(snrIn) * 7,
)
const noisy = aligned.map((v) => v + mixSigma * mixRng.gauss())
```

第二条序列换成画 `noisy`，图例名改成口径写明的写法：

```ts
{
  name: '解调输出（含噪声）',
  color: '#3ce3c6',
  points: noisy.map((v, i) => [i * dt + from * dt, v] as [number, number]),
},
```

结论的正常分支末尾追加一句（紧接三元式收尾的 `}` 之后）：

```
这条线按输出信噪比 ${fixed(outSnr, 1)} dB 标定了噪声（σ = ${fixed(mixSigma, 3)}），画出来的不是理想波形。
```

`distortion`、`measuredBand`、`outSnr` 的计算路径一字未改——噪声只加在准备画出去的那条数组上，读数仍读理想路径。

种子这样编：`MIX_SEED + mode*1009 + round(m*100)*31 + round(β*10)*17 + round(snrIn)*7`。四个滑块的取值域两两不重叠（`mode` 0–3、`m` 0.2–1.0、`β` 0.5–8、`snrIn` 5–25），乘子取不同质数后任意两档的种子都不同；`createRng` 内部再 `>>>0` 截断，等价于对 2³² 取模。同参数连算两次，`series[1].points` 逐点相等，`Math.random` 一次都没用。

## 测试（`tests/course.test.ts`，第 5 章新增 3 条）

1. 「换参数图必变」：`m=0.2` 与 `m=1.0` 的绘图序列最大逐点差 > 0.1；`snrIn=5` 与 `25` > 0.5。
2. 「噪声按输出信噪比标定，同一档两次算出来逐点相同」：`assert.deepEqual` 两次 `compute` 的 `series[1].points`；`name === '解调输出（含噪声）'`；两个 σ 不同的档相减，差值序列的均方根与 `√(σ₁²+σ₂²)` 相对误差 < 15%；`conclusion` 含「标定了噪声」。
3. 「三个读数仍走理想路径」：`m=1.0` 的 `解调失真=0.0%`、`输出信噪比=23.2 dB`；`β=8` → `57.4 dB`；`snrIn=5` → `-0.2 dB`。

断言 2 的写法有过一次返工：最初按下标逐点减 `series[0]`（消息，256 点）与 `series[1]`（解调，196 点），长度不同直接 `Cannot read properties of undefined (reading '1')`。改成「两档噪声相减」——两档的 `aligned` 相同、噪声独立，差值的均方根就是 `√(σ₁²+σ₂²)`，绕开了两列起点与长度不一致的问题。
