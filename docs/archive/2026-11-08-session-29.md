# 2026-11-08 · R52 滑块与数值框：拖动时不再每帧重跑仿真、不再每帧重画位图

## 判据原文（本轮要求）

> 五处滑块都是原生 input[type=range] 受控组件，onChange 直接 setState，拖动时每一次 input 事件都同步重跑一遍仿真，叠加六个图表组件每次渲染都重设 canvas.width/height（位图重分配加清屏），所以手感是一格一格跳。

> 第一件，新建 src/labs/ParamSlider.tsx，导出「标签 + 数值框 + 滑块」一体组件。数值框要有：type=number，输入过程中只改本地草稿不提交，回车或失焦才提交；提交时按 min/max 夹紧、按 step 对齐；非法输入回退到上一个有效值；aria-label 要写清楚是哪个参数。外观上数值框顶掉现在 label 行右侧那个 strong，无边框、同字号同字体、只在聚焦时显示边框，位置和宽度别让 label 行跳动。保留每个参数原有的 hint 文案，一个字不改。

> 第二件，写一个 useRafValue hook：input 事件只把最新值写进 ref，用 requestAnimationFrame 合帧，每帧最多提交一次 state。

> 第三件，六个图表组件的画布尺寸改成只在真变化时设。记住上一轮的 dpr 与实际宽高，一样就跳过，别再每次渲染都重分配位图；窗口缩放后仍要正确重绘。

> 截图里读数必须与改动前逐字一致。若某个页面改完仍不丝滑，别自己加旋钮，把页面名和拖动时的一帧耗时报给我。

## 为什么手感是「一格一格跳」

两件事叠在一起，都发生在同一次拖动里：

一是仿真。五处滑块的 `onChange` 直接 `setState(Number(event.target.value))`，浏览器一次拖动会连着发几十个 `input` 事件，每个都触发一次重渲染，页面里的仿真（星座 5,000 个符号、OFDM 200 个符号、卷积 11 个点）就跟着同步跑几十遍，主线程被占满，滑块的位移只能一格一格地补上来。

二是位图。六个图表的 `useEffect` 依赖里带着数据，每次重渲染都执行 `canvas.width = Math.round(width * dpr)` 与 `canvas.height = ...`。给 canvas 的 `width` 赋同一个值也会让浏览器丢掉整张位图并重新分配、重新清屏——尺寸没变，代价照付。

## 三样东西怎么改的

**`src/hooks/useRafValue.ts`（新）**：`input` 事件只把最新值写进 `latest` 这个 ref，再挂一个 `requestAnimationFrame`；帧回调里把 ref 取出来提交一次并清空。拖动过程中的几十个事件因此塌成一帧一次，最多每帧重跑一遍仿真。

**`src/labs/canvasSize.ts`（新）**：`syncCanvasSize(canvas, width, height, dpr)` 用 `WeakMap` 记住每个画布上一次的 `width / height / dpr`，四舍五入后的三元组没变就直接返回 `false`，一个像素都不碰；变了才赋值并更新记录。六个图表把原来那两行赋值换成这一行调用，`canvas.style.width / height` 照旧设——那是 CSS 尺寸，改它不重分配位图。

**`src/labs/ParamSlider.tsx`（新）**：标签行右侧原本是 `<strong>{value}{unit}</strong>`，现在是一个固定 `92px` 宽的 `input[type=number]`，透明底、透明边框、等宽字体、右对齐，`:focus` 才显边框。输入过程只改本地 `draft`，回车或失焦才走 `clampSnap`：先按 `min / max` 夹，再按 `min + round((v - min) / step) * step` 对齐，最后夹一次。空串与非数字回退到上一个有效值；`Escape` 也是回退。单位单独一个 `<span class="param-unit">`，不放进输入框——放进输入框就会被 `type=number` 当成非法字符悄悄吞掉，用户会以为单位丢了。

数值框**不走 rAF**：键盘输入本来就是一秒几下，合帧只会让数字慢半拍；只有滑块走工厂函数。
