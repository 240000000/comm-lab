## 一、刻度算法：等分 → nice step

原来线性轴两个分支都是「4 等分取 5 个点」，末点必然是端点本身，所以只要 `0` 不是 `xMin`，0 就不会有刻度。改法是把「步长」当自变量：

1. 先估一个数量级：`baseExp = Math.floor(Math.log10(span / 5))`；
2. 在 `baseExp - 1 … baseExp + 1` 三个十次幂里，各试 `1 / 2 / 2.5 / 5` 四档乘数，得到 12 个候选步长；
3. 每个候选步长数一遍「落在范围内的整数倍刻度有几根」，取最接近 5 根、且不少于 2 根的那个，得分相同取更小的步长；
4. 刻度值一律是 `k * step`，所以 0 本来就是某个整数倍——**只要 0 在范围内，0 一定有刻度**；
5. 浮点尾巴用 `Number(value.toPrecision(12))` 收掉，`|value| < step * 1e-9` 直接归 0，避免出现 `-0.0000000000000001` 这种刻度字；
6. 万一候选全不合适（范围退化），退回 `[min, max]` 两根。

`src/labs/niceTicks.ts` 是这个算法单独的一层（`niceTicks(min, max): number[]`）。抽出成独立模块不是为了分层好看，是因为 `CourseChart.tsx` 是 `.tsx`，node 无法直接 import——而这一轮的验收第一条就是「13 章逐章打印刻度数组」，纯函数放在 `.ts` 里，`node` 才能直接跑。

`CourseChart.tsx` 里横向四支变成：章节显式给了 `xTicks` → 用它；`logX` → 原来的整十次幂；`stack` → 原来的整数网格（堆叠柱数的是个数，不能出小数刻度）；其余 → `niceTicks(xMin, xMax)`。纵向同构，`logY` 与显式 `yTicks` 两条老路都不动。
