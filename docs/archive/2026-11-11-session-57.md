## 二、第 1 章：反例是重新设计的，不是加了个条件

这一条要先说清楚，因为它和「给 `failed` 多套一个 if」是两件事。

- 新增第三个参数 `计算口径`（`key: 'basis'`，两项 `按概率加权（对）` / `拿单次信息量当平均（错）`）。第 1 章因此从两参数变成三参数，`docs/tech-report.md` 课程视图表的「参数个数」列由 `check:docs` 从 `course.ts` 复算后报出，改成 3，没有手改。
- `failed` 改由这个参数触发：`const failed = basis === 1`。任何合法 p（0.01…0.99）在正确档下都是绿的；p 的滑杆照旧可拖、读数照旧跟着变。
- 错档下 `实测平均信息量` 直接拿 `I(p)` 顶上（不再按 p 与 1−p 加权抽样），结论说清「把单次信息量当平均，等于假设每个符号都同样罕见」。
- 正确档下三条读数与结论文本逐字维持原状（`1.00 / 1.000 / 1.000 bit`）。
- `failPreset` 指向错档：`{ p: 0.99, sample: 3, basis: 1 }`。
- `单次信息量 I(p)` 这条读数的 `warn` 从 `info < entropy` 去掉——p 是自由参数，合法取值不该标黄。

改前：p=0.99 正确口径下 `failed=true`（就是用户抱怨的「p 一动就红」）。
改后：正确档 p = 0.01 / 0.3 / 0.5 / 0.8 / 0.99 五档全 `failed=false`；错档 p=0.99 `failed=true`。

## 三、第 3 章：理论均值按档给，带心跟着走

- `ProcessStats` 加 `center`：平稳档为 0，非平稳档取观测窗口末时刻的期望 `c·T = PROC_DRIFT × timeMs/1000`（默认档 100 ms → 0.200）。
- `理论统计平均` 读数不再写死 `'0.000'`：平稳档仍 `0.000`，非平稳档报 `0.200`，hint 写明 `E[x(t)] = c·t` 随时间线性变化、带心取末时刻。
- `±4σ_T` 容许带的中心不再是 0，改用 `stats.center`；分类判据改为 `Math.abs(value - stats.center) > band`；`guides` 三条同样跟着走（`统计平均 0.200（末时刻 c·T）` / `0.326` / `0.074`）。
- 红线守住：带外比例仍是 **92.0 %**（探针实测过三种带心，只有 `c=0` 与 `c=cT` 在 100 ms 档给出 92.0 %，取 `cT` 与文档口径一致）；`failure` 档仍红；σ_T 三档 `0.036 / 0.146 / 1.127` 与改前一致——**注意这里第三个数是 `averages` 的标准差（1.127），σ_T 理论值本身是 `0.0316`，两者不是同一个量**。

改前：三档 `理论统计平均` 全为 `0.000`，容差带固定以 0 为中心。
改后：kind 0 → `0.000`、kind 1 → `0.000`、kind 2 → **`0.200`**；带外 `0.0 % / 0.0 % / 92.0 %`；同档连跑两次结论逐字相同。

## 五、两处与用户给的数不一致，按实算写

- **第 9 章 dt=0.2**：用户说约 8.0 dB，实算是 **9.1 dB**。`ρ(0.2)=0.8` → `10·log10(2 × 0.64 × 6.31) = 9.07 dB`；要得到 8.0 dB 得 ρ≈0.707（损失 3.01 dB）。dt=0.4 的 6.6 dB 与用户一致。读数与断言都按实算写。
- **第 1 章错档的比值**：用户说「实测均值与 H 的比值 ≥ 5」。p=0.99 时 `I=0.014 bit`、`H=0.081 bit`，比值的**方向是 I < H**（I/H = 0.17，H/I = 5.79）。断言写成 `Math.max(measured/entropy, entropy/measured) >= 5`，并在注释里说明方向；若按 I/H 口径写，这条在 p=0.99 处永远不成立。
