## 一、2DPSK：判决量从「两个实数相乘」改成复相关

旧模型（`shootBits`，`scheme === 3`）：

```ts
const a = Math.sqrt(2 * gamma)
const r1 = a + rng.gauss()
const r2 = (bit === 1 ? a : -a) + rng.gauss()
const product = r1 * r2
```

每个支路只有一路实噪声，正交支路被整个丢掉。按复基带口径，`r1`、`r2` 各应是「信号 + 两路独立噪声」，判决量取 `Re(r1·conj(r2))`；少了虚部噪声，判决量方差偏小一半，等效信噪比偏高，实测点系统性往理论线左侧挪。

新模型：

```ts
const a = Math.sqrt(2 * gamma)
const r1Re = a + rng.gauss()
const r1Im = rng.gauss()
const r2Re = (bit === 1 ? a : -a) + rng.gauss()
const r2Im = rng.gauss()
const product = r1Re * r2Re + r1Im * r2Im
```

`a = √(2γ)` 没动：复相关下 `Re(r1·conj(r2))` 的两项噪声各自独立，方差归一到 `Eb/N0 = γ` 的口径，与理论式 `0.5·exp(−γ)` 同口径。

| 输入 Eb/N0 | 理论 | 改前实测 | 改前/理论 | 改后实测 | 改后/理论 |
| --- | --- | --- | --- | --- | --- |
| 4 dB | 4.06e-2 | 2.42e-2 | **0.596** | 4.14e-2 | **1.020** |
| 6 dB | 9.33e-3 | 4.35e-3 | **0.466** | 9.20e-3 | **0.986** |
| 8 dB | 9.09e-4 | 5.00e-4 | **0.550** | 8.00e-4 | **0.880** |

改前三个比值是 0.596 / 0.466 / 0.550，与用户实跑的数字逐位一致（在 `46b7501` 的独立 worktree 上复现）。改后三档落在 0.88–1.02，都在 0.6–1.6 内。

10 dB 以上不比：20000 比特在 8 dB 只有 16 个错比特，10 dB 只剩 1 个，12 dB 是 0 个 —— 三档之间差的不是模型，是统计噪声。这条也写进了断言（`readouts[1].value * 20000 < 40`）。

## 二、2FSK 不再被相位误差判死

旧判据：

```ts
const collapsed = phaseDeg >= 40 && Math.abs(gainDb) < 0.5
```

`scheme === 1`（2FSK）的 `gainDb` 恒为 0 dB，所以 `collapsed` 对 2FSK 恒真 —— 一拖 φ 就标红，还给出「吃掉了整整 3 dB」。但本模型里 2FSK 的两路是正交的，理论式与仿真幅度都没乘 `cos²φ`，判红是判据漏了 scheme 条件，不是物理。

改法：加 scheme 条件。

```ts
// 2FSK 的两路正交，接收端比的是两路能量，φ 不进来，别拿 2PSK 的 cos²φ 判它。
const collapsed = scheme !== 1 && phaseDeg >= 40 && Math.abs(gainDb) < 0.5
```

结论句按 `phaseDeg` 分两档：φ=0 时保留原句；φ>0 时改写成「2FSK 不需要相干载波相位：两路正交各走各的，接收端比的是两路能量谁大，φ 只让两路一起缩一点，判决门限跟着缩，误码率不动。理论式和实测里都没有 cos²φ 这一项，相位误差 45 度对它零影响，实测仍贴着 Q(√(Eb/N0))。」

| φ=45° 时的档 | 改前 | 改后 |
| --- | --- | --- |
| 2ASK（scheme 0） | failed=false，理论 3.79e-2 / 实测 3.86e-2 | 一字未动 |
| 2FSK（scheme 1） | **failed=true**，理论 6.00e-3 / 实测 5.70e-3，结论「吃掉了整整 3 dB…」 | **failed=false**，理论 6.00e-3 / 实测 5.70e-3，结论改成「零影响」 |
| 2PSK（scheme 2） | failed=true，6.00e-3 / 5.85e-3 | 未动 |
| 2DPSK（scheme 3） | failed=false，9.09e-4 / 4.50e-4 | 未动 |

2FSK 的实测值改前改后同为 5.70e-3 —— 种子没变、仿真没变，变的只是「判不判红」。

## 三、FM：把「调频指数」真的做成调频指数（选甲）

原消息 `m(t) = 0.7sin2πt + 0.5sin(2π·1.5t)/1.5`，导数峰值是 1.2，所以 `Δf = 1.2β kHz`、`D = Δf/fm = 0.8β`。参数名却叫「调频指数 β」，理论式又按 `D = β` 写 Carson `2(β+1)fm` —— 名、实、式三者不齐。

选甲：把消息归一化到导数峰值 1，再让相位乘 `β·fm`，使 `D = β` 恰好成立。

```ts
const fmMsgPeak = 1.2
const fmMsg = (t: number) =>
  (0.7 * Math.sin(2 * Math.PI * t) + (0.5 * Math.sin(2 * Math.PI * 1.5 * t)) / 1.5) / fmMsgPeak
```

- 相位：`2πfc·t + beta * fm * fmMsg(t)`（原来乘的是未归一化的消息、系数 `beta`）
- 鉴频：`demod.map((v) => v / Math.max(beta * fm, 0.2))`（原来除 `beta`）
- `theoryBand = 2*(beta+1)*fm`、`gainDb = 3β²(β+1)` 都不用改 —— 它们本来就按 `D = β` 写的，改完才对得上。

**算术对不上的地方，如实记下。** 用户给选甲的验收数是「β=2、输入 25 dB 时输出 38.0 dB、带宽理论 7.8 kHz」。按甲的算式：

- 甲：Carson `2(β+1)·1.5 = 2·3·1.5 = 9.00 kHz`，增益 `3·4·3 = 36` → `+15.56 dB` → 输出 `25 + 15.56 = 40.56 dB`
- 乙（`D = 0.8β = 1.6`）：Carson `2(2.4+1.5) = 7.80 kHz`，增益 `3·2.56·2.6 = 19.97` → `+13.01 dB` → 输出 `38.01 dB`

即 38.0 dB 与 7.8 kHz 都是**乙方案**的数，与「选甲」不能同时成立。按甲的物理实现、断言用甲的真值（输出 40.6±0.2 dB、理论带宽 9.00 kHz、实测 7.00 kHz），并在断言里把 9.00 与 78% 一起钉住，避免以后再被改回乙而不报错。

| --- | --- | --- | --- | --- | --- | --- |
| 0.5 | 4.50 kHz | 2.00 kHz | 44%（报黄） | 3.00 kHz | 67%（报黄） | 25.5 dB |
| 1 | 6.00 kHz | 3.00 kHz | 50%（报黄） | 4.00 kHz | 67%（报黄） | 32.8 dB |

改后实测带宽整体上移、贴近 Carson 上限，β=2 与 β=4 不再报黄 —— 印证「名实对齐之后偏差本来就该变小」。输出信噪比四档一位未变（`25+10log10(3β²(β+1))` 与消息幅度无关）。
