## 三样东西

### 一、`docs/提交说明.md`：只写占位符

五节：包里有什么 / 先看哪个 / 怎么跑起来 / 怎么核对里面的数字 / 这份说明本身。正文里一个阿拉伯数字都没有，六个占位符 `{{TAG}}`、`{{TESTS}}`、`{{ASSERTIONS}}`、`{{PAGES_REPORT}}`、`{{PAGES_INTRO}}`、`{{FILES}}` 等打包时替换。

首版踩了一处：第四节写「对不上会退出码 1」，`1` 被自己的守门规则抓住（`docs/提交说明.md:34 具体数字（只许占位符）`）。没有放宽规则，改的是措辞：「对不上会以非零退出码结束并打印文件名与行号」。守门规则宁可严。

### 二、`scripts/pack.mjs`：一条命令

```
node scripts/pack.mjs --out D:/harness/work/_packtest/comm-lab-作品包-R50-test.zip
```

步骤：`git archive --format=zip --prefix=comm-lab/ <tag>` 打源码（天然只含已跟踪文件，自动排除 `.git`、`node_modules`、`dist`）→ `git ls-tree -r --name-only <tag>` 数源码文件 → `npm test` 输出解析测试条数 → `npm run check:docs` 输出解析断言条数 → pypdf 读两份 PDF 页数 → 替换六个占位符写成 `提交说明.txt` → 用 python `zipfile` 追加模式把两份 PDF 与说明放到**包根**（不是 `comm-lab/` 里）→ 最后打印条目数、文件数、字节数、解压字节数、sha256 前 16 位。

本机没有 `zip` 命令，追加这一步用 python 的 `zipfile`（标准库，零新依赖）。

两处实现上的坑：

- `git archive ... -o rawZip` 与后面追加写的 `outZip` 用了两个不同名字，包里会只有 PDF 没有源码。统一成一个。
- Windows 上 `execFileSync('npm', …)` 与 `execFileSync('npm.cmd', …)` 都起不来（`.cmd` 不能无 shell 直接 spawn，报错对象里 `status: null`、`pid: 0`）。改用 `execSync('npm test', { cwd: ROOT, encoding: 'utf8', maxBuffer: 64 * 1024 * 1024 })`。

### 三、打包后自检：不信打印

解压到临时目录，四条断言，任一不过 `exit 1`：

1. 解开的树里没有 `.git`、`node_modules`、`dist`；
2. 包根有 `comm-lab-技术报告.pdf`、`comm-lab-作品介绍.pdf`、`提交说明.txt`；
3. `提交说明.txt` 里搜不到 `{{`；
4. 两份 PDF 的页数与说明里写的一致。

第 3 条当场抓到自己：说明最后一节原本写着「把 `{{ }}` 占位符替换成…」，这行字本身带 `{{`，打包后残留检查直接报错。改成「把上面那些占位符替换成当场算出来的值」。

## 卡在哪

- **`git archive` 只能打已提交的状态**。这一轮的存档要写 zip 的实数，而 zip 又要从 tag 打，于是顺序只能是：写完代码与文档 → commit → `git tag R50` → 跑 `pack.mjs` 拿实数 → 把实数写进本文 → `git commit --amend` 并入 → `git tag -f R50` 重打（仍 52 个 tag）→ `npm run check:docs` → push。不 amend 的话，存档里的数就对不上它描述的那个 tag。
- 本轮只做试打包，产物在 `_packtest/` 且名字带 `-test`。11/16 正式换包是另一次：换 `--out` 路径、改网盘链接，`pack.mjs` 不动。
