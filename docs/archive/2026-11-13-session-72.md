# 2026-11-13 · R99 深度实验台入口抽成组件，教材栏文案改成实话

## 一、这轮要解决什么

用户报了两个界面问题，都很小，都是「说的和做的不一样」这一类。

第一个：页面上写着「另有实验台可以直接跳到对应的交互页」，第 4/8/11 章的数据里也确实写着 `labs: [{ label: 'OFDM 实验台', href: '#/ofdm' }]`，但 13 章全部实现之后，那三台链接一个都点不到——因为渲染 labs 的那段 JSX 只写在 `TodoScreen`（给「尚未实现」的章用的兜底屏）里。章一旦实现，走的就不是 `TodoScreen` 了，labs 从此没有任何人渲染。这是一段只会在旧状态下成立的代码。

第二个：教材栏写着「不落盘；书的章名只活在这一次会话里，刷新就回默认 13 章」。但 `src/App.tsx` 启动时已经 `void hydrate()` 把 IndexedDB 里的书架读回来了，刷新之后接着的是上次那本书，不是默认 13 章。这句话从加书架那一刻起就是错的，只是没人读出来。

## 二、入口点不到的根因

`src/labs/CoursePage.tsx` 里有两个屏：`ChapterScreen`（已实现的章）和 `TodoScreen`（未实现的章）。labs 的渲染原本长这样，只出现在 `TodoScreen` 末尾：

```tsx
{chapter.labs?.length ? (
  <div className="course-links">
    {chapter.labs.map((lab) => (
      <a key={lab.href} href={lab.href}>{lab.label}</a>
    ))}
  </div>
) : null}
```

11 月把 13 章补齐之后，`TodoScreen` 的命中率变成 0：任何一章都进 `ChapterScreen`，这段 JSX 永远不执行。而 `.course-links` 在 `src/App.css` 里连一条样式都没有——它本来就是个没长完的分支。

判断「数据还在不在」的办法很直接：`src/core/course.ts` 第 4 章的 `labs` 在第 2585 行、第 8 章在第 2631 行、第 11 章在第 2667 行，三处都在，`scripts/check-docs.mjs:569` 还在拿它们现算技术报告 1.6 表的那一列。所以数据没问题，问题全在渲染侧。

## 三、抽成 CourseLabs

新组件放在 `ChapterScreen` 之前，两个屏共用同一份：

```tsx
function CourseLabs({ labs }: { labs?: { label: string; href: string }[] }) {
  if (!labs?.length) return null
  return (
    <div className="course-labs">
      {labs.map((lab) => (
        <a className="course-btn" key={lab.href} href={lab.href}>
          去{/^[A-Za-z]/.test(lab.label) ? ' ' : ''}{lab.label}
        </a>
      ))}
    </div>
  )
}
```

`ChapterScreen` 里接在结论卡的 `.course-actions`（「让它失效 / 回到默认」那一行）下面，也就是同一行的下一行；`TodoScreen` 里替换掉原来的 `.course-links` 分支。`.course-labs` 补了一条样式（`display: flex; flex-wrap: wrap; gap: 10px; margin-top: 10px;`），窄屏自动折行；按钮沿用 `.course-btn`，与「让它失效」同色同尺寸，因为它就是同一类「跳走 / 触发」的动作。

`去` 后面那个空格是按 label 首字符判断的：`QAM 实验台`、`OFDM 实验台` 是拉丁字母开头，中间要空一格；`卷积码实验台` 是中文开头，不空格。这样三台分别是「去 QAM 实验台」「去 OFDM 实验台」「去卷积码实验台」，与用户描述页面时用的说法完全一致。

## 四、教材栏文案改回实话

原文（`.textbook-note`）：「PDF 不上传、不落盘；书的章名只活在这一次会话里，刷新就回默认 13 章。」

改后：「目录存在这台机器的浏览器里，刷新后还是这一本，要换书点「切换」；原文件按书架面板的「导入时同时保存原文件」开关决定存不存，存不存都不上传。」

三处都点到了：目录在本机浏览器（IndexedDB）、原文件按开关存不存、都不上传。「不上传」这半句必须留着——它是真的，也是这一块的卖点，删掉等于把唯一的好消息丢掉。同时把顶栏 lede 在非默认书分支里那句「目录只在内存里，刷新就回到默认 13 章」也改成「现在用的是你导入的教材，目录存在这台机器的浏览器里，刷新后仍是这一本。」——同一句假话在页面上出现了两次，只改一处等于没改。

## 五、数据一行没改

`src/core/course.ts` 这一轮没有改动，`git show --stat` 里根本看不到它。三处 `labs` 保持原样，label / href 一个字符都没动，`href` 仍然只有 `#/ofdm`、`#/qam`、`#/conv` 三种。R99 改的只是「这些数据由谁渲染、渲染在哪儿」。

## 六、守卫测试钉住两头

新增 `tests/courseLabs.test.ts`，三条断言，纯函数、不碰 DOM：

1. 技术报告 1.6 表「深度实验台」那一列，写成字面量 `{ 4: ['#/ofdm'], 8: ['#/qam', '#/ofdm'], 11: ['#/conv'] }`，其余 10 章为空数组；逐章与 `COURSE_CHAPTERS` 的 `labs` href `deepEqual`。
2. 把 13 章的 `labs` 展平，恰好是 `['#/ofdm', '#/qam', '#/ofdm', '#/conv']`，且每一项都在 `LAB_ROUTES` 里——防止有人写个 `#/foo` 出来，页面上点一下 404。
3. 每个 label 至少 2 个字，且不以「去」开头——「去」由组件补，如果数据里也写「去」，页面上就会出现「去去 QAM 实验台」。

这条测试测不出「界面上有没有按钮」，它钉的是数据与文档两头：一旦有人把 `labs` 删了、改了 href，或者报告 1.6 表与数据不一致，`npm test` 立刻红。真正的验收是截图与点击。

## 八、数字连带：359 → 362

三条新测试把测试总数从 359 推到 362。`npm run check:docs` 把测试条数与文件数写死在断言里，不改必红，所以只动了纯数字：

- `README.md` 三处、`docs/preview.md` 一处、`docs/works-intro.md` 一处、`docs/tech-report.md` 四处（其中 `31 个文件` 改成 `32 个文件`）。

## 九、这一轮的取舍与教训

- **只在一个屏里成立的代码，等于不存在。** labs 的渲染写在 `TodoScreen` 里时是对的，那时确实只有未实现的章才有入口；13 章补齐之后它变成了死代码，而页面上那句承诺还在。组件化的动机不是「复用」，是让「谁是唯一渲染者」这件事不再取决于哪个屏被命中。
- **文案与实现分头演进，迟早会互相打脸。** 书架从内存搬到 IndexedDB 时改了实现，没人回头看那句「刷新就回默认 13 章」。同一句假话在 lede 与 `.textbook-note` 各写了一遍，改一处不够——所以这轮把两处一起改。
- **守卫测试要钉能钉的那一头。** 测「界面上有没有按钮」得靠浏览器，成本高会没人跑；测「数据与文档对不对得上」是纯函数，几百毫秒。后者能挡住的是数据被误删、href 写错、报告与代码漂移这三类真事故。
- **红线与 check-docs 冲突时，选能让口径自洽的那一边，并把偏离写清楚。** 这轮动了九个数字，全部是测试条数连带出来的，提交与回复里都点了名；叙述一个字没碰，PDF 也没重导。
- **测试数变化是全局数字。** 加三条断言就会牵动五个文档、九个位置——这是 `check-docs` 的设计意图（数字不许手抄），代价是每加一条测试都得同步，且必须在一轮里同步完。
