# 2026-11-11 · 第 55 段（R82）

## 这一轮要的

把「教材导入」从课程视图里的一个按钮，改成这个产品的主入口：导入一本书之后先给一张账单（认到几章、几章能玩、其余几章为什么不给假仿真），每章后面写出认它的依据；教材本身做成一个内存里的书架（可再导入、切换、移除）；入口提到课程视图的最外层。只动界面层与一条匹配器的返回结构，13 章的计算与读数一个字都不许动。

## 一、根因：为什么它一直只是个按钮

三处结构性缺口，缺一处都做不成「入口」。

第一，`src/course/match.ts` 的 `matchChapter` 只返回 `{ topicId, score }`（`src/course/match.ts:13-18`）。分数是个数字，没法告诉用户「凭什么说这一章是第 6 章」——没有命中词，账单就只能写「已识别」，用户没法判断对不对、也没法指出哪条认错了。所以返回结构里必须把命中词带出来。

第二，导入的结果是直接塞进渲染的：`ImportPreview` 放着书名与章数，点「用这本书」就把 `imported` 状态一置、左树换掉。中间没有一步「先看账单再决定」。而账单单靠章节数是不够的——真书 13 章里能玩的可能只有几章，用户得先知道这个比例，再决定要不要拿它替掉默认的 13 章。

第三，教材没有地方存。`imported` 是一个「当前导入的那本」，再导入一本就把上一本顶掉，切换与移除无从谈起。要能切换，得先有并存的几本——也就是一个书架。

## 二、匹配器返回命中词

`MatchResult` 加 `hits: string[]`（最多三个，按分数与词长降序，长的、更具体的在前）。实现上把关键词表在 `NORMALIZED_KEYWORDS` 阶段就带出来源写法：原来的 `{ word: normalize(word), topicId }` 扩成 `{ word, label, topicId }`，`label` 存归一化之前的原文。命中时把 `label` 收进一条按 topicId 分的证据表，末尾取最终胜出那个 topicId 的证据。

**挑最优的那段判定逻辑一行没改**，所以 `topicId` 与改前逐条相同——这一点用两条测试钉住了：同一条章名改前改后 `topicId` 一致，且每个 `hits` 里的词都真的出现在章名里。

## 三、书架（`src/course/shelf.ts`）

`ShelfBook = { id, title, chapters }`，每章 `{ no, rawTitle, topicId, hits }`。默认书架上就是通信原理那本（13 章手写，`hits: []`）。

- `addBook`：同 id 换掉，否则追加。
- `removeBook`：默认那本不许删，书架至少留一本。
- `bookById`：找不到退回第一本（避免切到一半书没了把界面搞崩）。
- `nextBookId`：编号形如 `imported-N`，按现有书的序号递增，不撞车。
- `isPlayable`：`topicId` 有值**且** `chapterByNo(Number(topicId))` 真的存在——两重判据，防止关键词表里有个 topicId 而这版应用没有对应章。

**只在内存里**：不写 localStorage、不落盘，刷新就回默认 13 章。PDF 本身也仍然只读书签，正文一个字节都不留。

## 四、账单

三行汇总：`识别到 N 章` / `其中 M 章有可交互模型` / `其余 N−M 章：本书这部分暂未覆盖，识别不出来的章不提供只能看的假仿真。`

每章一行：章名 + 依据。能玩的写 `→ 数字基带传输系统，命中「基带」「眼图」`；认不出的写 `未识别到对应模型`。**没有「即将支持」这类空话**——测试里直接断言未命中的那句话只有一句、且不含这几个字。

## 五、教材栏提到最外层

课程视图顶部一条：`当前教材：通信原理（第 7 版）` + 「导入一本书」+「切换/收起」；展开是书架列表，每本一行「标题 + M / N 章能玩 + 用这本 / 使用中 + 移除」。默认那本的移除按钮是 disabled。

首页一个字没动：四张卡、hero、badge、页脚都没碰。
