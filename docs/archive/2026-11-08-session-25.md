## 为什么这句数会自己过期

`docs/tech-report.md` 里那两句数字不是算出来的，是上一轮打字打进去的。上一轮打完 R47 的 tag，轮次表从 48 行变成 49 行，`check-docs` 数的「表行数 = tag 数」这一条过了，但同一份文档的正文还写着「这张表 48 行里」「上面这张表 48 行，与 48 个 tag 一一对应」。

`check-docs` 不读散文，所以它没报——是文档自己跟自己打架。更麻烦的是这个错每打一个 tag 就复发一次：这轮改成 49，下轮打 tag 又变成 50。

所以改法不是把 48 改成 49，是把数字从散文里拿掉。

## 新加的那条断言

`scripts/check-docs.mjs` 里加了一段，扫 `docs/tech-report.md` 正文（跳过以 `|` 开头的表格数据行——那部分由「轮次表行数 = tag 数」管），五种写法逐个查：

| 写法 | 举例 |
| --- | --- |
| 这张表 N 行 | 这张表 48 行里 |
| 一共 N 个 tag | 一共 48 个 tag |
| N 个 tag 一一对应 | 与 48 个 tag 一一对应 |
| N 行，与 N 个 tag | 48 行，与 48 个 tag |
| `rev-list --count HEAD` 得 N 次提交 | 输出 N 次提交 |

命中就按 `{file, line, label, written, actual}` 记一条不符，打印文件名、行号、命中的原文和该改成什么，最后退出码 1。五种写法各算一条断言，所以断言总数 158 → **163**。
