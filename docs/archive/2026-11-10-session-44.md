## 一、修那处必抛的调用

R67 里文字层兜底写成了 `doc.getTextContent({ pageIndex })`——`PDFDocumentProxy` 上没有这个方法，书签为空的 PDF 一走到兜底就抛 `TypeError: doc.getTextContent is not a function`。改成两跳：

```ts
async function pageText(doc: PdfDocument, pageNumber: number): Promise<string> {
  const page: PdfPage = await doc.getPage(pageNumber)
  const content = await page.getTextContent()
  return content.items.map((item) => item.str).join('')
}
```

`PdfPage` 与 `PdfDocument` 两个接口都是本轮新写的结构化类型（`getPage(pageNumber): Promise<PdfPage>`、`numPages`、`getOutline`、`getDestination`、`getPageIndex`），**没有 `getTextContent`**——类型上就杜绝了同一个错误再犯一次。

取文本这一步抽成可注入的取数器，和已有的 `loadPdfjs` 一个路子：

```ts
export type PageTextLoader = (doc: PdfDocument, pageNumber: number) => Promise<string>

export async function scanTextLayer(
  doc: PdfDocument,
  loadPageText: PageTextLoader = pageText,
  limit = TEXT_SCAN_PAGES,
): Promise<{ lines: string[]; chars: number }>
```

### 假 doc 怎么测

测试里造一个 120 页的假 doc，`getPage` 把每次请求的页码记进 `calls`，`getTextContent` 把整页文本拆成单字符 items（模拟 pdf.js 的实际返回形状），第 3、11、40 页埋三章名：

```ts
function fakeDoc(pages: string[], numPages: number) {
  const calls: number[] = []
  return {
    calls,
    doc: {
      numPages,
      getPage: async (pageNumber: number) => {
        calls.push(pageNumber)
        return {
          getTextContent: async () => ({
            items: (pages[pageNumber - 1] ?? '').split('').map((str) => ({ str })),
          }),
        }
      },
    },
  }
}
```

断言四条：`TEXT_SCAN_PAGES === 40`、`calls.length === 40`、页码序列正好 1..40、`chaptersFromTextLayer(result)` 精确返回那三章。**测的是「翻多少页、每页拼成一行、章名抓得出来」，而不是喂一个现成的字符串数组**——这正是 R67 缺的那一层。

## 二、兜底认怂：没有文字层就说没有

```ts
export const MIN_TEXT_CHARS = 50

export function chaptersFromTextLayer(scan: { lines: string[]; chars: number }): OutlineEntry[] {
  if (scan.chars < MIN_TEXT_CHARS) return []
  return chaptersFromTextLines(scan.lines)
}
```

`chars` 是前 40 页去空白后的字符总数。真实场景里大量教材是纯扫描件——用户拿那本 146 MB 的书实测，`page.getTextContent()` 返回 items 0、pypdf 也抽不出字符，全书只有图片加 296 条书签。这类书走文字层兜底只会得到一屏噪声，所以少于 50 字符直接返回空数组，界面拿到空数组就提示「没有书签、文字层也抠不出章名（大概是扫描件）」，让用户手输。

加密与损坏统一收口到一条自己的错误类型：

```ts
export class PdfOutlineError extends Error {
  constructor(message: string) {
    super(message)
    this.name = 'PdfOutlineError'
  }
}
```

- `PasswordException` → 「这本 PDF 加了密码，读不了目录。请换未加密的版本，或者直接手动输章名。」
- 其它 → 「这本 PDF 读不动：文件可能损坏，或者用了不常见的编码。换一本试试，也可以手动输章名。」

`parsePdfOutline` 抛的永远是这两类之一，界面 `catch` 里 `instanceof PdfOutlineError` 直接用它的 `message`，不会再出现 `TypeError: xxx is not a function` 这种弹给用户看的东西。

## 三、worker：函数内取地址，起不来才退主线程

```ts
async function attachWorker(pdfjs: PdfjsModule): Promise<boolean> {
  const options = pdfjs.GlobalWorkerOptions
  if (!options || typeof window === 'undefined') return false
  try {
    const worker = await import('pdfjs-dist/build/pdf.worker.min.mjs?url')
    options.workerSrc = worker.default
    return true
  } catch {
    return false
  }
}
```

`?url` 是 Vite 的写法：拿到的是 worker 模块的 URL，worker 由浏览器自己起，主线程不解析。`parsePdfOutline` 里第一次失败、且 worker 曾经设上、且不是密码错时，才切 `data.slice(0)` 副本（pdf.js 会把传入的 ArrayBuffer transfer 走）重试：

```ts
if (workerAttached && !(error instanceof PdfOutlineError && /密码/.test(error.message))) {
  console.info('pdf.js 的 worker 没起来，已退到主线程解析。')
  return readOutline(pdfjs, data.slice(0), loadPageText, true)
}
```

**默认路径不带 `disableWorker`**——主线程解析只是退路，不是常态。

## 四、界面：导入 → 预览 → 用这本书 / 恢复默认

默认态由 `COURSE_CHAPTERS` 生成（`note: null`、`disabled: false`），导入态由 `imported.book.chapters` 生成：

- 命中：标题写 `第 N 章 · 标题`，`note` 写 `PDF 第 N 页`（页号 null 时写「PDF 页码未标」）；

两条保护：

```ts
const MAX_PDF_BYTES = 250 * 1024 * 1024
const SLOW_PARSE_MS = 15_000
```

超过 250 MB 直接报「这个文件超过 250 MB，太大了。换一本小一点的，或者手动输章名。」；解析挂表 15 秒后把 `slow` 置真，状态行追加「还在解析，大文件要等一会儿，可以继续等。」，但**不取消**。

内存约束写在界面上：「选一本 .pdf，只读它的书签；不上传、不落盘，刷新就回默认 13 章。」导入后换成「当前《书名》：13 章里 13 章能玩。PDF 不上传、不落盘，刷新即失效。」没有任何 `localStorage`、没有 `fetch`、没有 `File` 之外的落点。
