# 2026-11-08 · 会话 34 · R57

## 这一轮做什么

只改一个物理量：第 5 章 FM 的制度增益。R56 把它写成了 3β²/(2π)，那是验收方在 R56 引导词里给错了目标数（要求「β=1、25 dB 输入时输出落 21.8 dB」），不是推导错。R57 改回单音 FM 的标准式 3β²(β+1)，代码、注释、hint、测试、报告里那一句一起对齐，别的一个字不动。

## 改法

1. `src/core/course.ts:363-365` 注释整段重写：制度增益是输出信噪比与输入信噪比之比，两个功率之比，无量纲；单音 FM 的标准式 G = 3β²(β+1)，β=1 时为 6，即 +7.78 dB；解调器噪声按角频率积分的那个 2π 是单位换算，已经包含在该式的口径里，不能再除一次。
2. `src/core/course.ts:366-367` 的 `gainDb` FM 分支：`(3 * beta * beta) / (2 * Math.PI)` → `3 * beta * beta * (beta + 1)`。AM 的 `(2*m*m)/(2+m*m)`、DSB 的 `2`、SSB 的 `1` 三条不动。
3. `src/core/course.ts:417` 输出信噪比的 hint：`制度增益 3β²/(2π) = ` → `制度增益 3β²(β+1) = `。
4. `tests/course.test.ts` 那条测试改名并整体重写：从「β=1、25 dB 输入时输出信噪比落在 21.8 dB 附近」改成「…落在 32.8 dB 附近」，容差仍 0.15 dB；注释写 `3β²(β+1) = 6 → +7.78 dB；25 + 7.78 = 32.78`。再补两条断言把 β=2（40.6 ± 0.2）、β=3（45.3 ± 0.2）一起钉住。
5. `docs/tech-report.md:174` 那句手抄的旧读数：`输出信噪比掉到 8.6 dB` → `输出信噪比翻成 -0.3 dB`（β 取第 5 章默认 2、输入 6 dB，按改后的式子实算为 −0.32 dB，不是抄的）。
6. `docs/tech-report.md` 轮次表加 R57 一行（表 57 行 → 58 行，与 58 个 tag 对齐）。

## 改前 → 改后读数

| --- | --- | --- |
| 0.5 | 15.8 dB | 25.5 dB |
| 1 | 21.8 dB | 32.8 dB |
| 2 | 27.8 dB | 40.6 dB |

## 卡在哪

`docs/tech-report.md:174` 那句是 R41 时代手抄的 8.6 dB，check-docs 不校验它（不在断言清单里），所以 R56 改增益时它没报红、就这么留了下来——这正是「数字靠手抄就会漂」的老毛病。这次按实算改成 −0.3 dB，并在轮次表里写明 β 与输入取值，别人复算得出来。
