## 做了什么

### 一、规格白名单（`src/answer/diagram.ts`）

- 只认一种形状：`{ kind: 'psk-time', bits, bitRate, carrierHz, showBlock }`。逐项校验，任何一项不合规整体返 `null`——不转型、不补默认值、不截断。
- 派生出四个纯函数：`symbolSeconds`（= 1 / bitRate）、`diagramSeconds`、`bitBoundariesMs`（`bits.length + 1` 个边界，含首尾）、`cyclesPerSymbol`（整数倍返 N，否则 `null`）、`diagramFootnote`（按 N 是否整数切换两句底注文案）。

### 二、图形（`src/labs/AnswerDiagram.tsx`）

- canvas 980 逻辑宽，`devicePixelRatio` 上限 2；三段纵向排布：框图 208、基带 96、带通 156，共用同一条横轴的 `scaleX`。
- 框图五块圆角矩形，横向四条箭头，载波源在下、箭头向上进乘法器；框内小字写位串片段、`单极性→双极性`、`cos ω_c t`。
- 基带段画 `basebandLevel` 给出的电平，纵轴 ±1 虚线；带通段按 `1 / (48 · carrierHz)` 采样再按像素抽稀（上限 24000 点），值取 `level × carrierSample`。
- 码元边界竖虚线从框图顶端贯到带通段底部（内部分界 0.72 alpha，两端 0.42）；每位上方标 0/1；带通段上方按 scheme 标相位（2PSK/2DPSK 标 `0` / `π`，2ASK 标「有载波 / 无」）；横轴刻度到 ms。
- 底注三行：现算的 `f_c·T_b`、相位映射说明、码元数与波特率与载波频率。

### 三、接进答题模式

- `provider.ts`：`AnswerMeta.diagram?: PskTimeDiagram`，`parseModelAnswer` 里 `diagram: parseDiagram(row.diagram) ?? undefined`；`SYSTEM_PROMPT` 加 diagram 的形状与边界说明，并明确「别自己造别的图形类型、别把波形写成坐标数组」。
- `SolvePage.tsx`：卡 3 在「模型作答」徽标下渲染 `<AnswerDiagram>`；没有图就写「这道题的文字答案里没有配图。」；`diagramScheme` 按题面正则挑 2DPSK / 2ASK / 2PSK。
- 物理原语补在 `src/core/course.ts`：`basebandLevel(scheme, bit)`、`carrierSample(carrierHz, seconds)`、`differentialBits(bits)`——组件里不另写一份波形。

### 四、测试与验图

- `tests/diagram.test.ts` 三条：白名单八种拒绝 + 合规原样通过；边界数 = 位数 + 1 且第 2 条边界正好等于 `T_b`（7 位、2000 Baud → 0.5 ms 一段）；`2400/1200 = 2` 时底注落在峰点、`2500/1200` 非整数时切到「不在峰点」。
- 截图用临时 Vite 页（已删）挂四张图，CDP 裁 `.answer-diagram` 保存；另用一条独立校验脚本把画布像素与「按同一套物理公式算出的期望轨迹」比对，四张图各 240 个采样列全部命中（±2 px），证明画的确实是 `level × cos(2πf_ct)` 而不是示意线。
- 一张真 bug：不画框图时原先会在时间轴上方写一行「本题没有要求」的提示，与基带标题重叠，删掉。
