## 这一轮做什么

只修一件事：课程视图的滑块拖动跟手。上一轮 R53 拿「p50/p95 一样」「同步阻塞 76.8 → 0.5 ms」交差，两条都不合格——无头浏览器的 rAF 被钳在 ~7 ms，看不出 20 ms 级的抖动；同步阻塞量的是按下那一刻，跟拖动中每帧的耗时不是一回事。这一轮把「拖动期间每帧到底多久」量出来，按测量改，再用同一套测量验证。

## 量法

有头 Edge（不是无头）+ CDP，同一台机器、同一个静态服务器：

1. `npm run build` 后把 `dist` 复制到 `/d/harness/tmp/site/comm-lab`，`python -m http.server 8011 --bind 127.0.0.1`。
2. Edge 带 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling` 起有头窗口，页面 `#/course`。
3. 页面里装三组探针：`requestAnimationFrame` 记每帧时间戳（帧间隔 = 相邻差）、`input` 事件记每个 value、`PerformanceObserver({type:'longtask'})` 记 >50 ms 的任务。
4. CDP `Input.dispatchMouseEvent` 在第一个 `input[type=range]` 上按下、从左到右 90 步、每步 `mouseMoved`（`GAP=11` ms），松手后读 `.readout-value`、`.course-conclusion`、`.course-conclusion.failed`。
5. 同一套脚本再跑第 4 章（其 compute 只要 0.04 ms）作对照：若第 4 章也黏，问题就不在 compute。

两个坑记在这里，省得下次再踩：目标页 `visibilityState` 为 `hidden` 时，`Input.dispatchMouseEvent` 每条要等 5004 ms 才返回（渲染器不提交帧，输入 ack 挂起），必须先 `Page.bringToFront` + `Emulation.setFocusEmulationEnabled({enabled:true})`；`Page.navigate` 到只有 hash 不同的同一 URL 不会重新载入文档，页面里的 listener 与 rAF 循环会累加（moves 会变成 180/270），改先设 `location.hash` 再 `Page.reload({ignoreCache:true})`。

## 改法

1. **新增 `src/labs/dragCommit.ts`**：`createDragCoalescer<T>()` 返回 `{ begin, push, end, live, dragging }`。拖动期间 `push` 隔一次提交一次（先算一帧再跳一帧，按下后第一帧立刻有反馈），`end` 用最后一次完整参数补算。被省掉的只有中间帧，松手那一刻走的是全精度路径。
2. **`src/labs/ParamSlider.tsx`**：拖动期间**一个字节都不往 DOM 里写**。滑块改成非受控——`defaultValue={value}`、`ref={rangeRef}`，只在 `value` 变化且不在拖动中时用一个 `useEffect` 把 DOM 值追上去（`draggingRef` 挡住拖动期间的回写）。`onPointerDown` 置 `draggingRef = true` 并通知父组件开始拖动；`onPointerUp / onPointerCancel / onBlur` 收尾并通知父组件补算。
3. **`src/labs/CoursePage.tsx`**：拆出 `params`（滑块与标签读它，每次事件都更新）与 `committed`（`chapter.compute` 读它，拖动期间隔帧更新），`dragRef = useRef(createDragCoalescer<Record<string, number>>())` 负责把前者节流成后者；`pick / onFail / onReset` 三条路径同时写两份。
4. **`tests/course.test.ts` 加 3 条**（234 → 237）：不拖动时每次变化都提交；拖动时隔一次提交一次、松手用最后值补算，并且断言「同参数下拖动路径的 readouts / conclusion / failed 与直接 compute 一字不差」；两次拖动各自独立，第二次不继承上一次的跳过位。

## 卡在哪

1. 第一版用 `useState` 存拖动中的值（`dragValue`）解决「thumb 被拽回」，p95 从 20.8 掉到 7.1，但长任务从 0 条变成每次拖动 2–7 条（55–76 ms）。用 R57 的 HEAD 构建在同机另起 8012 端口做同期对照，基线仍是 0 条，所以不是环境漂移；把 `dragValue` 去掉、只留 coalescer 的变体 A 长任务回到 0–1 条，但 thumb 又被拽回、拖不到底（`finalV` 只有 0.35 而不是 1）。
2. 结论是「每帧把受控 `value` 写回 DOM」本身会周期性触发一次同步的布局+绘制，正好落进 50 ms 以上。于是换成非受控写法：拖动期间浏览器自己管 thumb，React 一个字都不写，长任务回到 0 条，p95 保持 7.2。
3. 一度想用 `useRef` 在渲染期读 `.current` 挡回写，被 oxlint 的 `react(refs)` 规则判成 warning（0 warnings 是硬指标），改参数化到事件回调里才算过。
