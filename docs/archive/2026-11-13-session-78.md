# 2026-11-13 · 会话 78（R106：有原件的身份错配）

## 用户原话

R106：修「有原件」的身份错配。一、src/course/shelfDb.ts 的 pdfs 记录（或 books 记录）加 pdfMeta 字段，存 { numPages, head: string }，head 取首页文字前 80 字（复用 src/course/pdfText.ts 的 extractDocText，只取第 1 页）；savePdf 签名跟着改成 savePdf(id, blob, meta)。二、src/course/pdfSource.ts 的 loadDoc 打开文档后，读 meta 比对 doc.numPages，不符返回 { status: 'mismatch', expected, actual } 这种显式状态，不许静默返回 document；PdfPane 收到 mismatch 就显示「本机存的原文件与这本书对不上（目录 13 章，原件 N 页），请重新导入」并留「清除原件」按钮。三、shelfStore 的 storePdf 遇到 DEFAULT_BOOK_ID 直接返回失败，理由「内置书没有原件」，不写库。四、新增 clearPdf(id)：删 pdfs 那条记录、从 pdfBytes 里去掉、目录与章节一个不动；书架面板每本书（含默认那本）都有「清除原件」，只在有原件时显示。红线：不改 src/core/course.ts，不动首页四卡与 hero，不引新依赖，13 章 compute 零变化，R105 的解析缓存与 6:4 分栏不许回退。验收要有五张截图：默认那本无原件、导入一本真 PDF 后正常看书、人为把默认那本写进错误 blob 后显示 mismatch（用 CDP 直接往 IndexedDB 塞一条假的验证）、清除原件后回到无原件、清除后书架行状态变回「内置书，随应用生成」。测试至少四条（pdfMeta 往返、numPages 不符返回 mismatch、默认那本拒绝写原件、clearPdf 只删 blob 不动目录）。另外把默认那本的藏书位清干净，截图必须是一本真书的「通信原理」或者一本导入的真 PDF，不要再拿技术报告冒充教材。报 npm test、npm run check:docs、构建体积增量。

## 这轮要解决什么

R105 只查「有没有 blob」，不查 blob 是不是这本书的：往默认书塞任何 PDF 都会被当成教材原文。R105 的 `hasPdf` 还把默认书排除在原件之外，塞错了连提示都看不到；书架面板也只有「移除」，没有「清除原件」。

## 改了什么

- `src/course/shelfDb.ts`：`PdfMeta = { numPages, head }`、`PdfRecord = { blob, meta }`、`readPdfRecord`、`deletePdf`；`savePdf(id, blob, meta)` 把身份一起写进 pdfs 记录。
- `src/course/pdfSource.ts`：`LoadResult`（`ok` / `mismatch{expected,actual}`）、`readPdfMeta`（首页文字前 80 字，只读第 1 页）、`loadDoc` 比对 `meta.numPages`，不符就销毁并返回 mismatch；`loadFromPdfjs` 的 `destroy` 落到 `loadingTask` 上（pdfjs 6 的 `PDFDocumentProxy` 没有 destroy）。
- `src/course/shelfStore.ts`：`storePdf` 遇到 `DEFAULT_BOOK_ID` 返回失败「内置书没有原件」，不写库；新增 `clearPdf`，只删 pdfs 记录与 `pdfBytes`，目录与章节不动。
- `src/labs/bookStorage.ts`：导入时先 `readPdfMeta(file)`，连同 blob 一起传下去。
- `src/labs/PdfPane.tsx`：收到 mismatch 显示「本机存的原文件与这本书对不上（目录 N 章，原件 M 页），请重新导入」并给「清除原件」；清除后重载。
- `src/labs/CoursePage.tsx`：`hasPdf` 去掉 `!usingDefault`（默认书也可以有原件，才可能显示 mismatch）；传 `chapterCount`。
- `src/labs/ShelfPanel.tsx`、`src/App.tsx`：书架面板每本有原件时显示「清除原件」。

## 取舍与教训

- 只存「有没有」不够，要存「是不是」：`numPages` + 首页头 80 字是最小身份，误配时能说清差在哪。
- pdfjs 6 的 `destroy()` 在 loadingTask 上，`PDFDocumentProxy` 只有 `cleanup()`；用假 doc 的测试会掩盖这一点。
- 默认书的原件路径被 R105 的 `!usingDefault` 堵死，identity 校验就永远走不到；补录时先放开这条路径再验。
