## 二、三处对不上

1. **测试条数过期。** 作品介绍第 33 行写「测试 241 条，分布在 16 个文件里」，当前是 362 条、32 个文件。这句从 R47 留到现在，中间加了 121 条测试、多了 16 个测试文件，没有人碰过它。
2. **EVM 被写成了「四档都是 25.33%」。** 报告表里 12 dB 四档是 25.18 / 25.19 / 25.33 / 25.35（BPSK / QPSK / 16QAM / 64QAM，种子 20261027，按页面默认 20,000 比特）。同一个 Es/N0 下理论 EVM 确实与阶数无关，差出来的 0.17 个百分点来自不同阶数的符号数不同（20,000 / 10,000 / 5,000 / 3,334 个符号）造成的估计波动。原文把 16QAM 的实测值当成了四档共同值。
3. **图注把曲线点的分母写成了读数条的分母。** 第 89 行写「读数条带分母 2,331 / 80,000」，而截图 `qam-12db.png` 上读数条是 610 / 20,000。2,331 / 80,000 是下方曲线 12 dB 那个点（每点 20,000 符号 = 80,000 比特）。两组数各自都对，写进同一句就错了。

## 三、为什么守卫没拦住

- 测试条数规则是 `/([\d,]+) 条测试/`，只认「数字在前、条测试在后」。第 3 行的「362 条测试」能过，第 33 行的「测试 241 条」词序相反，正则根本没匹配上，241 就这样在规则底下站了一年多。
- EVM 规则把数字绑在 `p12(16).evmPercent` 上，数字抄错能查出来，但查不出「四档都是」这个断言——另外三档的 EVM 它没有取值。
- 图注那句没有任何规则。读数条的分母与曲线点的分母是两套数，全靠人眼看。

## 九、取舍与教训

- **守卫要按断言的语义写，不能按数字出现的位置写。** 一个数字换了词序就漏检，这条规则等于没存。
- **「都是某个值」比「某个值是 X」强。** 守一个集合的时候必须把集合里每个成员都取出来，只绑一个成员，恰好会把错的平均掉。
- **图注和图片是两份证据。** 图注里的数必须和图片上的读数条同源；曲线点的分母再真，也不能拿来当读数条的分母。
- 目标页数（29 页）没有因为补两行而涨，说明轮次表区还有余量；下次再补行仍要重数页数。
