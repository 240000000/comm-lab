## 三、第二件：书架搬进 `src/course/shelfStore.ts`

搬家，不是新建功能。书架的数据层（`shelf.ts` 的 `addBook / removeBook / billOf / evidenceOf / nextBookId`）本来就有，缺的是「首页也能读到同一份状态」这条线：

- `CoursePage` 里原来是 `useState<ShelfBook[]>([defaultShelfBook()])` + `useState<string>(DEFAULT_BOOK_ID)`，两个 state 只活在那个组件里；首页要显示书架，就只能再存一份，两份必然走散。
- 现在 store 持有 `{ books, activeId }`，`commit(next)` 换对象后逐个通知订阅者；`useShelf()` 用 `useSyncExternalStore` 取快照。`setActive` 同 id 不通知，`importBook` 只加不切（切不切由调用方决定），`removeBookById` 删当前书时把 `activeId` 退回默认那本。
- `CoursePage.tsx` 的 `useState` 换成 `const { books, activeId } = useShelf()`，`setShelf(addBook(...))` → `importBook(added)`，两处 `setActiveId(...)` → `setActive(...)`，`dropBook` → `removeBookById(id)`。导入、账单、未覆盖提示的逻辑一行没动。
- 仍然是纯内存：没有 `localStorage`、`sessionStorage`、IndexedDB，也不碰 `location`。刷新就回默认那本——这是被验收的一条，不是缺陷。

`tests/shelfStore.test.ts` 六条：初始同引用、导入只加不切、切换通知一次且同 id 不重复、退订后不再收到、删书四种情况（默认删不掉 / 删非当前不动当前 / 删当前退回默认 / 删不存在不改）、重置回默认。

## 四、第三件：`ShelfPanel` 与 `ModulePanel`

两块都只吃 props：

- `ShelfPanel`：`books / activeId / importState / onPick / onRemove / onImport`。一行一本，四个数（总章、可玩、未覆盖）全部由 `billOf(book)` 现算，不写死；默认那本标「默认」且没有移除按钮；导入的书有「移除」。文件输入是真的 `<input type="file" accept="application/pdf">`，用 1×1、`opacity: 0` 藏在 `label` 里（不用 `display: none`，那会让读屏器和键盘都摸不到），选完把 `value` 清空，同一个文件选第二次仍然触发。
- `ModulePanel`：四列「章 / 书上原字标题 / 命中词 / 状态」。第二列用 `chapter.rawTitle`——书上怎么写的就怎么显示，这一列是让人核对目录解析对不对；改过的全称放在别处，不许混进来。第三列用 `evidenceOf(chapter)`，认不出来的行它自己就是「未识别到对应模型」。状态列可玩写「可交互」，整行链到 `#/course?no=N`；不可玩灰显写「暂无仿真」。表底用 `billOf` 汇总：「共 13 章：13 章有仿真、0 章暂无仿真。」
- 首页的导入助手放在 `src/labs/bookImport.ts`：后缀 → 250 MB → 懒加载 `pdfOutline` → 书签/文字层为空 → 抛错，四条分支各一句人话，三条文案按定稿写。「懒加载」这条沿用课程视图的做法，`pdfjs` 不进主包（build 里仍是单独的 `pdf-*.js`）。
