## 为什么这句数总差 1

这句话写的是「截至 Rn，一共多少次提交」，锚点是 `git rev-list --count HEAD` —— 那就是 HEAD 此刻的位置。可文档改完还要提交两次（存档、文档），提交完 HEAD 又往前走，句子立刻过期。R40 之前是差 1，R42 之后差 2（存档与文档两笔），每轮都得追一次，追的动作本身就是下一次过期。

改口径：锚打 tag 的那一笔，`git rev-list --count R43`。tag 是不可变的，锚住之后这句话永远成立，后面再怎么提交都不影响它。

当场输出：`git rev-list --count R43` = 85，`git rev-list --count HEAD` = 86（HEAD `34a77ae`），`git tag -l | wc -l` = 48。

第一处（`:440`）：

```
截至 R43，`git tag -l` 一共 48 个 tag，`git rev-list --count R43` 一共 85 次提交。
```

前半句「截至 R43」保留，只把命令与数字换成 tag 锚点后的值。这句后面紧接的「上面这张表 48 行，与 48 个 tag 一一对应」不动，表行数与 tag 数仍是 48 对 48。

第二处（`:448`）：`85 次提交里 37 次没打 tag`，同句末尾 `R11 之后的 25 次是存档补写`。自洽验算：85 − 48 = 37，37 − 12（R1–R10 那段的 12 次）= 25。中间那份罗列（9 次修正类 + 3 次初始骨架、CI 与 README 首版）一个字符没动。
