# 2026-11-08 · R53 课程视图：不再每帧读布局，把重渲染面收窄到被拖的那一项

## 判据原文（本轮要求）

> 这一轮只做一件事：让课程视图的滑块也丝滑起来。不要碰视频、不要碰实验台已经丝滑的部分、不要动任何读数。

> 第一件，`src/labs/CourseChart.tsx` 不要再每帧读布局。现在 :55 是 `const width = canvas.clientWidth || 720`，每次渲染都触发强制同步重排。改成用 ResizeObserver 把宽度缓存进一个 ref，绘制时读那个 ref，初始值给 720。仓里 `src/labs/HomeBackdrop.tsx:298` 已经有现成的 ResizeObserver 写法，照它抄。注意三点：一是 observer 要在 cleanup 里 disconnect；二是宽度真的变了才重绘，没变就不动；三是首次挂载时如果 observer 还没回调，用 720 先画一版，回调后补画，不要出现空白图。

> 第二件，把课程视图的渲染面收窄。`src/labs/CoursePage.tsx` 里给 `ChapterScreen` 和 `Control` 外面包 `React.memo`，把 onChange 用 `useCallback` 固定住（现在是每帧新建闭包，memo 不生效等于没做）。目标是拖动一个参数时，只有那个参数对应的滑块、图表和读数需要更新，左侧 13 项目录不要跟着重渲染。注意别把 params 整体作为 memo 依赖，那样每帧都变、memo 白做；依赖传具体那一项。

> 验证必须给出数字，不要只说感觉好了。做法：用 CDP 在课程视图第 6 章（最重的一章）和第 4 章（最轻的一章）各做一次脚本化拖动，连续派发 500 毫秒的 input 事件，页面里用 requestAnimationFrame 采样帧间隔，算出 p50 和 p95 毫秒数，改前改后各测一次，两组数一起报出来。判断标准是 p95 明显下降、且拖动过程中读数与参数始终同步。另外照 R52 的老办法起双站（检出 R52 那个 tag 做基线），逐档读 DOM 比对读数字符串，mismatches 必须是 0，第 1 到第 13 章都要过一遍。

> 如果按上面两件改完 p95 还是降不下来，停下来，加一个临时探针把 compute、React 提交、canvas 绘制三段的耗时分别量出来报给我，不要自己凭感觉继续调。

## 改了什么

`CourseChart.tsx`：`clientWidth` 从"每次绘制都读"改成"只在 ResizeObserver 回调里读"。新增 `widthRef = useRef(720)`；原来内联的 `useEffect` 绘制体抽成 `draw = useCallback(...)`，依赖仍是 `[series, xLabel, yLabel, logX, logY, bars, stack, guides]`；`drawRef` 每次渲染同步成最新 `draw`，再由 `useEffect(() => { drawRef.current = draw; draw() }, [draw])` 触发重绘；另一个只跑一次的 effect 建 `ResizeObserver`，`observe(canvas.parentElement ?? canvas)`，回调里 `Math.round(canvas.clientWidth || 720)` 与 `widthRef.current` 相等就 return，不等才写 ref 再 `drawRef.current()`；挂载时先 `measure()` 一次，有真实宽度就先写进 ref 并立刻画一版，所以不会出现 720 宽的白图；cleanup 里 `observer.disconnect()`。

`CoursePage.tsx`：`Control`、`ChapterScreen` 以及新抽的左侧目录 `CourseTree` 三个组件都包 `memo`；`Control` 收 `paramKey` 与按 key 提交的 `onChange`，内部用 `useCallback` 把 `handleChange` 钉住，`memo` 的依赖是 `param`（单个参数对象）与 `value`，不是整体 `params`；`pick`、`setParam`、`onFail`、`onReset` 全部 `useCallback`，`setParam` 走函数式 `setParams((prev) => ({ ...prev, [key]: value }))`，所以 `setParam` 的依赖是空数组、永远稳定。
