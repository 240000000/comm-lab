> 这一轮只做一件事：让课程视图的滑块也丝滑起来。不要碰视频、不要碰实验台已经丝滑的部分、不要动任何读数。

> 第一件，`src/labs/CourseChart.tsx` 不要再每帧读布局。现在 :55 是 `const width = canvas.clientWidth || 720`，每次渲染都触发强制同步重排。改成用 ResizeObserver 把宽度缓存进一个 ref，绘制时读那个 ref，初始值给 720。仓里 `src/labs/HomeBackdrop.tsx:298` 已经有现成的 ResizeObserver 写法，照它抄。注意三点：一是 observer 要在 cleanup 里 disconnect；二是宽度真的变了才重绘，没变就不动；三是首次挂载时如果 observer 还没回调，用 720 先画一版，回调后补画，不要出现空白图。

## 改了什么

`CourseChart.tsx`：`clientWidth` 从"每次绘制都读"改成"只在 ResizeObserver 回调里读"。新增 `widthRef = useRef(720)`；原来内联的 `useEffect` 绘制体抽成 `draw = useCallback(...)`，依赖仍是 `[series, xLabel, yLabel, logX, logY, bars, stack, guides]`；`drawRef` 每次渲染同步成最新 `draw`，再由 `useEffect(() => { drawRef.current = draw; draw() }, [draw])` 触发重绘；另一个只跑一次的 effect 建 `ResizeObserver`，`observe(canvas.parentElement ?? canvas)`，回调里 `Math.round(canvas.clientWidth || 720)` 与 `widthRef.current` 相等就 return，不等才写 ref 再 `drawRef.current()`；挂载时先 `measure()` 一次，有真实宽度就先写进 ref 并立刻画一版，所以不会出现 720 宽的白图；cleanup 里 `observer.disconnect()`。

`CoursePage.tsx`：`Control`、`ChapterScreen` 以及新抽的左侧目录 `CourseTree` 三个组件都包 `memo`；`Control` 收 `paramKey` 与按 key 提交的 `onChange`，内部用 `useCallback` 把 `handleChange` 钉住，`memo` 的依赖是 `param`（单个参数对象）与 `value`，不是整体 `params`；`pick`、`setParam`、`onFail`、`onReset` 全部 `useCallback`，`setParam` 走函数式 `setParams((prev) => ({ ...prev, [key]: value }))`，所以 `setParam` 的依赖是空数组、永远稳定。

## 一、`src/labs/CourseChart.tsx`：不再每帧读布局

原来 `useEffect` 第一行就是 `const width = canvas.clientWidth || 720`，每次绘制都强制同步重排。现在：

- `const widthRef = useRef(720)`，绘制时只读 `widthRef.current`，`clientWidth` 只在两处读——首次挂载时量一次、ResizeObserver 回调里量一次。
- 绘制体提成 `const draw = useCallback(() => {…}, [series, xLabel, yLabel, logX, logY, bars, stack, guides])`，再用 `drawRef` 转手，供 observer 回调调用，避开依赖数组里塞 observer 的死循环。
- 挂载 effect 依赖 `[]`：`const host = canvas.parentElement ?? canvas`；先 `const initial = measure()`，与 720 不同才写 ref 并 `drawRef.current()`——挂载即先按 720 画一版，不会留白图；`ResizeObserver` 回调里 `next === widthRef.current` 直接 return，真变才写 ref 再画；`observer.observe(host)`；cleanup 里 `observer.disconnect()`。

写法照的 `src/labs/HomeBackdrop.tsx:298` 那套（读取缓存进 ref、回调里比对再重画）。

## 二、`src/labs/CoursePage.tsx`：重渲染面收窄到被拖的那一项

- `Control`、`ChapterScreen` 都包了 `memo`；左侧 13 项目录单独抽成 `memo` 的 `CourseTree({ current, onPick })`——拖动参数时它不重渲染。
- 原来是每渲染新建闭包，`memo` 等于没包。现在四个 `useCallback`：`pick`（换章，依赖 `[]`）、`setParam`（`setParams((prev) => ({ ...prev, [key]: value }))`，依赖 `[]`）、`onFail`/`onReset`（依赖 `[chapter]`）。
- `Control` 的 props 是 `{ paramKey, param, value, onChange }`，内部 `const handleChange = useCallback((next) => onChange(paramKey, next), [onChange, paramKey])`，`select` 与 `ParamSlider` 都传它；**依赖只传 `param` 这一项与 `value`，不传整体 `params`**。
- 三个组件定义必须放在 `export function CoursePage()` 之前，否则 `TS2448: Block-scoped variable 'CourseTree' used before its declaration.`（`ChapterScreen` 同）。另外 `CoursePage.tsx` 文件末尾 HEAD 起就是两个连续 `}`，删掉最后一个会报 `TS1005: '}' expected.`——那不是我多写的，保留原样。
