# 2026-11-14 · session 84 · 书栏可拖宽 + Chrome 141 白屏的兼容层

## 用户原话（要点）

- R114：「书栏可拖宽，只动布局，不动识别与渲染」——默认 45%、最小 300 px、最大 60%，分隔条 8 px、hover 变色、`cursor: col-resize`；双击复位；左右键每次 16 px，`role="separator"` 与 `aria-valuenow` 百分比；宽度只存组件 state，不写 localStorage、不写 IndexedDB；收起书栏时分隔条不渲染。
- R115：「只做浏览器兼容层，标题就写 R115 补 Map.prototype.getOrInsert 与 getOrInsertComputed」——同一台机器、同一本书、同一个线上构建，Edge 157 正常，Chrome 141 打开 484 页全白，报 `TypeError: this.#n.getOrInsertComputed is not a function`。用户已双向实测：Chrome 141.0.7390.77 两个方法都是 undefined，Edge 157.0.4341.46 都是 function，`Promise.try` 与 `Promise.withResolvers` 两版都有。

## 这一轮要解决什么

R114 是纯视觉问题：书栏固定 405 px 时页面缩到 345 px 宽、正文只有 5 px 高，「一边看课本一边做交互」不成立，所以把分栏做成可拖、可键盘调、可复位，并且宽度不落盘。R115 是真故障：pdf.js 6.5.438 每页 render 都会调用 `Map.prototype.getOrInsertComputed`，Chrome 141 没有这两个方法，于是每页都抛异常、画布全空。修法是补两个方法，而不是降级 pdf.js 或换 legacy 入口。

## 逐文件改动

- `src/labs/CoursePage.tsx`（R114）：常量 `BOOK_MIN = 300`、`BOOK_MAX_RATIO = 0.6`、`BOOK_DEFAULT_RATIO = 0.45`、`BOOK_STEP = 16`；`bookWidth` 与 `bookUsable` state、`layoutRef`/`paneRef`/`drag` ref；`clampBookWidth` 夹在 300 px 与 60% 之间；布局用行内 `gridTemplateColumns: 264px minmax(0, 1fr) 8px ${bookWidth}px`；`.course-book-resizer` 走 `onPointerDown` + `setPointerCapture`、`onDoubleClick` 复位、`onKeyDown`（左右 ±16 px、Home 复位），`role="separator"`、`aria-valuenow` 百分比、`aria-valuemin` 按 300 px 折算；`ResizeObserver` 观察布局容器，窗口变化时重新夹紧。
- `src/labs/book-pane.css`（R114）：`.course-layout.with-book` 改 `264px minmax(0, 1fr) 8px minmax(300px, 45%)`；新增 `.course-book-resizer`（8 px、`cursor: col-resize`、`touch-action: none`、hover/focus 变蓝）；窄屏媒体查询里隐藏分隔条。
- `src/compat.ts`（R115，新建）：`defineMethod(name, value)` 用 `Object.defineProperty(Map.prototype, name, { value, writable: true, configurable: true, enumerable: false })`；两个方法各自 `if (typeof proto.getOrInsert !== 'function')` 才定义，原生存在时不动。`getOrInsert(key, value)` 命中返回现值、否则写入并返回；`getOrInsertComputed(key, callback)` 命中返回现值且不调回调，否则调一次 `callback(key)`、写入并返回。
- `src/main.tsx`（R115）：首两行注释 + `import './compat.ts'`，位置在 `StrictMode` 之前，确保早于 pdf.js 的动态 import。
- `tests/compat.test.ts`（R115，新建，四条）：两个方法存在且可调用；`getOrInsert` 不覆盖已有键；已有键时 `getOrInsertComputed` 的回调一次都不调；键不存在时回调只调一次且拿到 key 本身。

## 判据里被否掉或改掉的

- 一开始把 `aria-valuemin` 写死 30，但 300 px 在 1088 px 可用宽下是 28%，改按 `Math.round(BOOK_MIN / usable * 100)` 现算。
- 键盘自检第一次在拖到 300 px 之后做，读数与预期不符；改在默认 45% 处做才稳定（`aria-valuenow` 有渲染延迟，宽度是准的）。
- 截图脚本按 `aria-label` 含「樊昌信」挑书架行，点到的是上一轮清过原件的旧书，进课程视图后书栏不出现；改成「找含 `.shelf-clear` 的那一行再点」。
- `npm run preview` 不能用来验带 base 的构建：它对 `/comm-lab/assets/*.js` 返回 index.html，页面 root 是空的；改用自写静态服务按前缀剥路径。
- 场景 B 第一次读出页码 `1`：脚本设完页码就被书自身的页码映射改写；重跑并在 0.8 s、3.3 s 各读一次，确认稳定在 22。
