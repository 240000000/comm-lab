## 病根：把「稀罕的那一侧」当成了单次信息量

原来的实现是 `return -log2(Math.min(p, 1 - p))`。它把「事件发生」和「事件不发生」两条互补的消息当成同一件事，取概率较小的那一支，于是 I(p) 关于 p = 0.5 镜像：p = 0.99 和 p = 0.01 都得到 6.64 bit，曲线像个山谷。

教材定义只有一支：某条消息携带的信息量是 −log2(它自己的概率)。p = 0.99 的消息几乎必然发生，它只带 0.0145 bit；p = 0.01 的消息很稀罕，它带 6.64 bit。I(p) 应当一路单调下降，在 p = 1 处趋于 0，而不是在两端翘起。

错口径还顺着叙事往外漏：旧结论默认「单次和平均会一起掉」，于是失效判定只能靠一个外部阈值 `p >= 0.9`；而这个阈值与屏幕上的数没有关系，改一个 step、改一个默认值，它就可能和读数打架——这正是 R31 记下的那条教训。

## 五处怎么改的

1. `src/core/course.ts` 的 `selfInfo`：注释四行换成一句「单次信息量按定义就是 −log2 p，p 越大它越小，p→1 时趋于 0」，函数体改成 `return -log2(p)`。`grep "Math.min(p, 1 - p)"` 现在是 0 命中。
2. 读数：第一条 `单次信息量 I(p)` 的 hint 从「−log2 min(p, 1−p) = …；值钱的是稀罕的那一侧」改成「−log2 p = …；概率越大，这一次带来的信息越少，p → 1 时趋于 0。这一条是单次的理论值，下一条才是平均」。它的 `warn` 也跟着从 `p >= 0.9` 换成 `info < entropy`：警示条只在两条线真的分开时亮。
3. 失效档：`const failed = info < entropy`。两条曲线只在 p = 0.5 相交，p > 0.5 时单次必然小于平均，判据自己就从读数里长出来，不再另编一个数。「让它失效」按钮仍把 p 设到 0.99。
4. 三分支结论全部重写：失效档讲「单次只带 0.01 bit，可平均仍有 0.081 bit，因为那 1% 的『不发生』一次就值 6.64 bit——一个事件的信息量，不等于整条源的信息量」；p = 0.5 讲「两条线都到 1.00 bit，这是标尺」；p < 0.5 讲「单次 6.64 bit 很值钱，可平均只有 0.081 bit」。
5. 刻度：`CourseChart` 加两个可选 props `xTicks?: number[]`、`yTicks?: number[]`，另外 12 章不传、走原来的自动算法；`CourseView` 同步加两个可选字段，只有第 1 章填 `[0.01, 0.25, 0.5, 0.75, 0.99]` 与 `[0, 2, 4, 6]`。显式刻度用 `formatExact()`（`String(Number(value.toFixed(6)))`）出字，不会出现 `0.010`。传了 `yTicks` 就不再留 8% 的头顶空白，轴顶锁到数据端点 7.2，正好接上「当前 p」那条竖线的上端。
