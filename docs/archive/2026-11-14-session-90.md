# 会话 90 · R121 没答案就说清楚

## 用户原话要点

- 删掉 `SolvePage.tsx:156` 与 `:158` 两处 `?? problemByChapter(chapter)`：离线只按题面匹配，匹配不到就 null。
- `pickProblem` 抓不到带宽不许退回该章第一道——同样是猜。
- 答案卡分三态，文案不许混：A 没定位到章节、B 定位到第 N 章但题库没有、C 模型调用失败（加一句「可以先用内置三道示例题」）。
- 卡片 1 顶部常驻说明：离线只认内置三题，接上端点可解任意题，有端点时自动消失。
- 三条测试 + 两张截图（任意题 → B 态、示例题 → 正常答案），一个 commit + tag R121。

## 这一轮要解决什么

上一轮的答案卡只有「有答案」和「还没定位到题目」两态。定位到第 4 章却匹配不到题时，`?? problemByChapter(chapter)` 会把该章第一道（5 kHz、49.8 kbit/s）顶上去——用户传的是 2 kHz、20 dB，屏幕上却出现 49.8，属于用假答案回答真问题。

## 做了什么

- `src/answer/bank.ts`：`pickProblem` 改为严格匹配——同章多题必须带宽对得上（`/(\d+(?:\.\d+)?)\s*kHz/i`），题面给了 S/N 时 `snDb` 也要相等；任一步对不上返回 `undefined`。新增 `OFFLINE_ONLY_HINT`、`NO_CHAPTER_HINT`、`NO_SAMPLE_HINT_OFFLINE/WIRED`、`noSampleHint()`、`MODEL_ERROR_TAIL`（放 `.ts` 是因为仓库没有 `.tsx` 测试能力）。
- `src/labs/SolvePage.tsx`：`pickChapter` 去掉兜底；答案卡三态；B 态两个按钮「用该章示例题试试」（有题才显）与「怎么配置」（展开一行说明，不跳外链）；C 态错误话术补一句「可以先用内置三道示例题。」
- `tests/answerBank.test.ts`：第 1 章任意题面返 undefined、2 kHz/20 dB 不被兜底成 49.8、3 kHz/5 kHz 正向锁定、`noSampleHint` 两态文案；另把旧用例里「看不出带宽 → capacity」的兜底断言改成 undefined。
