# 每轮收尾清单

不管这轮改了多少东西，收尾都照着这张单子走一遍，走完再提交。漏项在 R3、R4 各发生过一次（INDEX 里没补当轮那行），所以第 5 条单独标出来。

1. **跑三样**：`npm test`（必须 `fail 0`）、`npm run build`、`npm run lint`，三样都过再往下走。
2. **对文案**：README 的模块表格、当前版本、用例数，页面上的说明——只写这一轮真做出来的东西，不写没实测的数字。
3. **写存档**：在 `docs/dialogues/` 的会话文件里追加本轮分节，用户侧逐字照录；AI 侧按 A 规则先写进存档、再从存档复制进回复，写完不再改字。
4. **拼文件清单**：`node /d/tmp/splice-stat.mjs`（定位 `### 文件清单` 后的代码块，两轮拼接校验稳定），提交后用 `git show --stat HEAD` 比对。
5. **补 INDEX**：`docs/dialogues/INDEX.md` 加一行，写清轮次、tag、commit 号和一句「这轮做了什么」。**这条漏过两次，不再靠记性。**
6. **提交与打标**：功能提交信息带 `[Rn]`，`git tag -a Rn`，两者一起推 `git push --tags`。
7. **等 CI**：查 `api.github.com/repos/240000000/comm-lab/actions/runs`，确认本轮 commit 的 run 是 `conclusion=success`；红了先修，不往下走。
8. **线上验**：打开 `https://240000000.github.io/comm-lab/`，本轮涉及的路由用无头浏览器跑一遍 DOM 与截图，能和本地对上就贴上证据。
9. **记一笔**：今日日志、白板进度、交接账本按需更新。

## 为什么是清单而不是记性

INDEX 作用是让评委不必读完整份存档就知道每轮改了什么。它漏一行，那一轮在索引里就不存在了——评委会以为这一段没做。这种事适合做成固定动作：每轮都做，做完打勾，不依赖当时记得。
